## 铁律（违反即前功尽弃）

```
❶ **标注阶段只读代码，不运行任何 detector**
   —— 看到的第一个数字会锚定判断（第 5–7 次"检查写错"的教训）

❷ **不把结构层结论外推到 capability 层**
   —— 结构 relation 漏掉 ≠ capability verdict 必然漏掉

❸ **reachable_chain = 0 ≠ capability absent**
   —— 它等于"能力存在但链路未被证实"

❹ **GT 必须先冻结，再跑 detector**
   —— 顺序反了就是循环校准
```

## 已知的坑（避免重踩）

| 坑 | 表现 | 处置 |
|---|---|---|
| **实现已冻结** | 不能改 lexer/locator/schema/weights/thresholds/verdict | 要改必须先停 P4 + 回归验证 |
| **`agentegress` region bug** | P0 层未修，evidence weighting 有未量化扰动 | 已隔离（A 类），修复进下一 baseline |
| **大文件超时** | 2.5MB+ 的导出/分析会 SIGTERM | 用 `*_MAX_FILE_MB` / `*_TRUNC_MB` 环境变量控制 |
| **`id()` 缓存** | 已修，但模式值得记 | 键用 `(id, len)` |
| **验证脚本自身会错** | 已实测 7 次 | 每个 FAIL 先定性：实现错/检查错/探针错 |
