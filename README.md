# AgentEgress

AI 客户端数据外传审计器 —— **审「正在用的工具本身」，不审你要装的东西。**

`v0.2.2` · 只读 · 零依赖 · 不联网 · 不外传

---

## ⚠ 先说它的根本局限（不放在最后）

**它是「字符串出现频率」的检测器，而它想回答的是「数据流」问题。**

这个差距有实测证据，而且**不是补模式能填的**：

| 绕过方式 | 实测检出 |
|---|---|
| 危险串在运行时拼接（`['a','b'].join('')`） | **0** |
| base64 编码字面量 | **0** |
| `new Function` / 动态构造 | 部分（2/5） |
| 逻辑放进 `node_modules`（默认配置） | **不读**，需 `--include-vendor` |

前三条是**方法的先天上限**：语义等价的代码在文本上可以完全不出现。
加强模式库只能抬高攻击方成本，而这里的成本增量是"写一个 `.join('')`"。

> **本工具能回答**：「代码里**是否有**已知形态的外传线索？」
> **本工具不能回答**：「这个客户端是否真的偷传了你的文件？」
>
> 把它当裁决器用是误用。它的输出是**线索与覆盖面台账**，不是判决。

还有一条会随时间恶化的：模式库、指纹库、阈值都是**无日期、无版本**的硬编码常量，
而**补充模式库这个动作本身会静默降级已有发现**（归一化的固有缺陷）。
所以"未检出"的保质期 ≈ 最近一次模式库更新的时间。

---

## 它回答两个问题

现有 AI 安全工具都在问"我要装的 skill / 插件 / MCP 安全吗"。AgentEgress 问的是另外两个：

| 问题 | 模块 |
|---|---|
| 我正在用的这个客户端，**传过什么**？ | M1 数据目录扫描 + M2 打包清单还原 |
| 它**能不能传**？ | M3 客户端静态审计（能力画像） |

**第二个问题才是重点。** 对 ZCode 全仓做关键词扫描，`PostObject` / `snapshot/upload-credential` / `repoSnapshot` 三个串的命中数都是 **0**——触发条件确实被删干净了。但触发条件被删，不等于能力被删：入口摘掉了，通道还在。只审"当前行为"就会漏掉"暂时休眠的能力"。

## 快速开始

```powershell
# 基础体检（M1 + M2）
python agentegress.py

# 只扫一个工具
python agentegress.py --tool zcode

# 出报告（Markdown / JSON / 单文件 HTML）
python agentegress.py -m reports/scan.md -j reports/scan.json -H reports/scan.html

# 启用 M3 静态审计（自动定位已装客户端）
python agentegress.py --static -H reports/scan.html

# 指定审计目标（目录或 app.asar）
python agentegress.py --static-path "%LOCALAPPDATA%\Programs\ZCode\resources\app.asar" -H reports/zcode.html
```

**默认扫描范围**：用户数据目录（`~/.<tool>`、`%APPDATA%`、`%LOCALAPPDATA%`）和标准安装目录（`%LOCALAPPDATA%\Programs\<Tool>`）。
装在其它盘、自定义目录的客户端扫不到——指纹库不硬编码任何一台机器的盘符，请用 `--static-path` 指过去。

**注意 `--static` 的跳过行为**：标准位置找不到任何可审计目标时，M3 会**静默跳过**——
不报错、不影响 M1/M2 的结果，也不在输出里单列「没找到」。
想知道实际扫到了什么，看报告里的**覆盖台账**（候选 → 读到 → 真正跑正则），或直接用 `--static-path` 指名路径。

**Windows 注意**：控制台读中文可能乱码，但报告文件编码是正确的。建议直接看 `-H` 产出的 HTML。

## 三个模块

| 模块 | 做什么 | 状态 |
|---|---|---|
| **M1** 数据目录指纹库与扫描器 | 识别各 AI 客户端的数据目录、快照残留、pending 密文、异常体积 | ✅ |
| **M2** 打包清单还原器 | 从明文元数据还原「传了哪些文件、多少字节、成功没有」 | ✅ |
| **M3** 客户端静态审计 | 解包 app.asar / 读源码，判定「有没有外传能力」 | ✅ v0.2 |

## M3 判定算法（精度说明）

粗糙的做法是"关键词计数"。本工具做了三层区分：

### 第一层 · 区域分级

先把源码切成 `代码 / 字符串 / 注释` 三类区域（轻量词法扫描器，非完整解析）。

> 「代码里调用了 `createCipheriv`」和「注释里提到了 AES-256」是两个完全不同量级的证据。

| 区域 | 系数 |
|---|---|
| 代码区 | 1.00 |
| 字符串字面量 | 0.85 |
| 注释区 | 0.15 |

### 第二层 · 文件分级

| 类别 | 系数 |
|---|---|
| 生产代码 | 1.00 |
| 配置 | 0.90 |
| 类型定义 | 0.30 |
| 测试 | 0.25 |
| 文档 | 0.15 |
| 第三方 / 构建产物 | 0.10 |

> 同一句话出现在 `README.md` 和出现在 `src/main/index.ts` 里，含义天差地别。

### 第三层 · 有界评分

```
单个模式贡献 = 最高单条基础分 × 多样性系数
多样性系数 = 0.85 + 0.15 × min(命中文件数, 5) / 5
能力总分 = 各模式贡献之和
```

**一个模式只贡献一次。** 因为能力判定问的是"有没有这种能力"，而不是"被调用了多少次"——298 个文件的生产代码库里，telemetry / retry 这类常规调用动辄命中几十次，累加会让分数随仓库规模线性膨胀。

### 等级判定（三个条件同时满足）

| 等级 | 分数 | 模式数 | 文件数 |
|---|---|---|---|
| confirmed | ≥18 | ≥3 | ≥2 |
| likely | ≥8 | ≥2 | ≥1 |
| possible | ≥3 | ≥1 | ≥1 |

**强单证据抬升**：`upload-credential` 这种词几乎不可能是巧合，单个模式也能抬到 likely——但仅当它出现在生产代码 / 配置里时。

### 触发方式推断

在证据行 ±3 行的上下文里找信号词，推断是「自动」还是「用户主动」。

> 这是**推断不是事实**。ZCode 的教训正是「同一个架构，触发条件一改性质就变了」。

## 能力边界（必读）

**能做**：发现快照残留、还原打包清单、检测跨工作区采集、展示开关话术落差、判定客户端外传能力。

**不能做**：
- ❌ 不能证明数据是否已被服务端**接收 / 删除** —— 本地没有痕迹能证明这一点
- ❌ 不能检测**零本地痕迹**的外传（传完就删、不留状态文件的客户端）
- ❌ 不能区分「尝试」与「成功」—— 那需要网络层证据
- ⚠️ M3 是**静态**审计：读到"有这个能力"不等于"这个能力被用在了你身上"
- ⚠️ 指纹库与模式库都有滞后性，新工具、新版本可能未覆盖

> 本地取证的正确表述是「**有这种能力 / 尝试过 / 打包了这些**」，不是「应该没事」。

## 设计约束

- **只读**：所有操作都是 `scandir` / 读文件
- **零依赖**：只用 Python 标准库
- **不联网**：不发起任何网络请求
- **不自动处置**：只输出证据与建议，执行由人决定
- **结论可回溯**：每个判定都能点回到 `文件:行:内容`

## 测试现状

`tests/verify.py` 是主验收，上面「快速开始」跑的就是它，**它是绿的**。
但它不是全部测试——下面这些是**独立**的，不包含在 verify 里，状态也不一样：

| 测试 | 当前状态 | 如何运行 | 说明 |
|---|---|---|---|
| `tests/verify.py` | 全部通过 | `python tests/verify.py --quick` | 主验收。其中的**合成回归**用 `tests/cases-synthetic.json`（样本随仓库分发，克隆即可跑）；**真实样本回归**用 `tests/cases.json`，依赖 `refs/` 下的外部克隆，缺样本时跳过并显式计数 |
| `tests/p05/test_p05.py` | **1 / 5 PASS —— 未修** | `python tests/p05/test_p05.py` | Role Evidence Probe 验收。五个用例里有四个仍是 FAIL（角色判定偏保守，大量落入 `unknown`）。这是真实状态，**不要因为 verify 全绿就认为这里通过了** |

合成回归里带 `xfail` 标记的条目同样是**已知缺口**，不是被放水的断言：
断言值按样本的设计意图写死，工具没达到就显示「已知缺口 N 项」；
一旦某天达到了，会报 XPASS 并提示把该条从 xfail 移除。
